If you are looking for a Next.js agency, you are usually deciding two things: whether Next.js is the right foundation, and who should build on it. This guide covers both.

## What Next.js is, briefly

[Next.js](https://nextjs.org/docs) is an open-source React framework. It lets each page be rendered on the server, generated ahead of time, or run in the browser, and it includes routing, image optimisation and server-side code in one project. That flexibility is the point: a content page and an application screen can live side by side, each rendered the way it should be.

## When Next.js is a good fit

- **Search matters.** Pages are delivered as HTML from the server or built in advance, so search engines and slow phones get content without waiting for JavaScript.
- **Content and application together.** Marketing pages, a logged-in area and an admin panel can share one codebase, design system and deployment.
- **More than one language.** Locale-based routing with separate URLs per language fits naturally. See [bilingual architecture](/writing/multilingual-architecture).
- **Custom integrations.** Server-side code can talk to payment, delivery, CRM or internal systems without exposing keys to the browser.
- **Room to grow.** Starting with a site and adding a portal or dashboard later does not require a different stack.

## When it may not be

- **A simple, team-edited site.** If the need is a blog or a few pages edited by a non-technical team, a hosted platform may be the better trade. Next.js can be paired with a content management system, but that is a project of its own.
- **An internal-only tool.** Server rendering adds little when search does not matter, though Next.js still works.
- **Nobody to maintain it.** Any custom codebase needs a developer for changes. Plan for that before you start.

## Questions to ask a Next.js agency

1. Which router and version do you build on, and why? Next.js has two routers, the App Router and the older Pages Router. Ask which they use for new work and how they keep up with major versions.
2. How do you decide the rendering strategy for each page? A good answer names which pages are static, which are server-rendered and why.
3. How will we edit content? In code, in message files, or through a content management system, and who can make which changes.
4. Where will it be hosted, and whose account is it? Next.js can run on a managed platform or on your own server, as the [deployment documentation](https://nextjs.org/docs/app/getting-started/deploying) describes. **The account should be yours.**
5. How do you check performance? Ask for named thresholds, such as Google's [Core Web Vitals](https://web.dev/articles/vitals), and how often they are checked.
6. Is the code typed and documented? TypeScript and a handover guide make the next developer's job possible.
7. What happens at handover? Repository, database schema and migrations, environment guide and deployment documentation.
8. Can I see a live Next.js project you built? Open it on your phone, in both languages if you need two.

## Next.js agency: common questions

### Is Next.js good for SEO?

It gives you the technical foundation: server-rendered or pre-built HTML, per-page metadata and fast pages. Rankings still depend on content and links, which no framework provides.

### Is Next.js only for large projects?

No. It works for a small marketing site as well as a large application. The question is whether you need what it offers, or whether a hosted platform would cover the need with less to maintain.

### Can I move my existing site to Next.js?

Usually, yes, page by page or all at once. Keep the URLs where you can and redirect the ones that change, as Google's [site move guidance](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes) describes. A [technical audit](/writing/technical-audit-before-rebuild) first shows what is worth keeping.
